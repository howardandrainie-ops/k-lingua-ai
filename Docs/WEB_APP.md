# 網頁版（PWA）：不用簽章、不用 Mac，iPhone 和電腦都能用

網址：**https://howardandrainie-ops.github.io/k-lingua-ai/**

網頁版和 iOS 版用的是**同一份教材**（12 單元、60 課、665 個單字），學習邏輯從 iOS 版逐一移植，並用相同的測試案例驗證。它不需要 App Store、不需要開發者帳號，也不會像免費簽章那樣 7 天過期。

## 安裝到 iPhone 主畫面

1. 用 **Safari** 打開上面的網址（一定要用 Safari，Chrome 等 App 在 iPhone 上不能加入主畫面成為獨立 App）。
2. 點下方的 **分享** 按鈕 → **加入主畫面** → **加入**。
3. 之後從主畫面的 K-LINGUA 圖示開啟：全螢幕、沒有網址列，用起來像一般 App。
4. 第一次開啟後，整個 App 和教材都會存在手機上，**沒有網路也能上課、練習、複習**（AI 對話與語音辨識除外）。

**建議同時做：** iPhone **設定 › 輔助使用 › 朗讀內容 › 聲音 › 韓文**，下載「加強版」或「高品質」語音，示範發音會自然很多（網頁版用的就是 iPhone 內建的韓文語音）。

## 在電腦上使用

用 Chrome 或 Edge 打開同一個網址即可。網址列右邊的「安裝」圖示可以把它安裝成獨立視窗的 App。電腦版的好處：

- 語音辨識在 Chrome／Edge 最穩定。
- 打字輸入韓文比較快（需要在作業系統加入韓文輸入法）。
- 螢幕大，看文法說明和報告比較舒服。

## 學習紀錄存在哪裡？會不會不見？

- 紀錄存在**這台裝置、這個瀏覽器**的本機資料庫（IndexedDB），不會上傳到任何伺服器。
- **手機和電腦的紀錄不會自動同步。** 要搬移，請到 **設定 › 備份與搬移** 匯出備份檔，再到另一邊匯入。
- 加入主畫面的網頁 App，不受 Safari「7 天沒用就清除網站資料」的規則限制；App 也會向瀏覽器申請「持久保存」。
- 下面這些操作**會刪掉紀錄**：刪除主畫面圖示、在 Safari 設定中清除網站資料、在電腦上清除瀏覽器資料。**請定期匯出備份**，可以用分享選單存到「檔案」或 iCloud Drive。

## 語音辨識：容易有問題嗎？

老實說，這是網頁版最不穩定的部分。有兩種辨識方式，可以在 **設定 › 語音辨識** 切換：

| 方式 | 優點 | 缺點 |
|---|---|---|
| **瀏覽器內建**（預設） | 免費、不需要金鑰 | 需要網路；iPhone 上要開啟「設定 › 一般 › 鍵盤 › 啟用聽寫」；在「加入主畫面」的模式下，不同 iOS 版本表現不一，**必須在你的手機上實測** |
| **AI 語音辨識** | 不依賴瀏覽器支援；可以重播自己的錄音 | 需要 OpenAI 或 Gemini 的 API Key（Claude 不支援語音）；錄音會上傳到該服務；每次辨識約 1–3 秒 |

如果兩種都不能用，所有題目都可以改用鍵盤作答，只有「快速反應」需要語音。

無論哪一種，發音回饋都是「**語音辨識比對**」，不是發音評分：辨識器只告訴我們它把你的聲音聽成什麼字，無法判斷語調、音長和送氣強度；發音不準也可能被自動修正成正確的字。所以 App 不顯示任何「發音分數」。

## 和 iOS 原生版的差異

| 功能 | 網頁版 |
|---|---|
| 課程、Pattern Drill、SRS、診斷、錯誤本、報告 | ✅ 和 iOS 版相同 |
| 示範發音 | ✅ 使用裝置內建語音 |
| AI 情境對話（Claude／OpenAI／Gemini） | ✅ 瀏覽器直接呼叫 API；金鑰存在瀏覽器本機資料庫，**沒有 iPhone 鑰匙圈的加密保護**，請不要在別人的裝置上輸入 |
| 語音辨識 | ⚠️ 見上一節 |
| 快速反應 | ⚠️ 瀏覽器規定麥克風要由使用者按下才能啟動，所以時限是 4 秒（iOS 版 3 秒），計時包含按麥克風的時間 |
| 每日提醒 | ❌ 沒有。網頁無法在手機上排定本機通知；可以用 iPhone「捷徑」App 的「個人自動化」每天定時打開 K-LINGUA |
| iCloud 同步 | ❌ 沒有，用備份檔手動搬移 |

## 更新

每次程式更新推送到 GitHub，網站就會自動重新部署。App 下次連網開啟時會在背景下載新版本，畫面下方出現「已下載新版本」時，點「重新載入」即可。學習紀錄不受更新影響。

## 驗證方式

每次推送都由 GitHub Actions（`.github/workflows/web-deploy.yml`）執行：

| 項目 | 內容 |
|---|---|
| 單元與整合測試（Vitest） | 核心邏輯（從 iOS 版的測試案例移植）＋本機資料庫整合，共 136 項 |
| 端對端測試（Playwright） | 在 **WebKit（Safari 的引擎，iPhone 尺寸）** 與 Chromium 上實際點按、輸入韓文：診斷、課程、Drill、SRS 四面向複習、錯誤本、報告、AI 設定與對話（攔截網路）、備份還原、離線開啟 |

**測試沒有涵蓋、需要你在手機上確認的項目：**

- iPhone Safari 上真正的語音辨識與麥克風（測試中用模擬的辨識器，只驗證辨識結果之後的評分與紀錄）
- AI 語音辨識的錄音流程（WAV 轉檔與 API 請求有單元測試，實際錄音沒有）
- 真正呼叫 AI 服務（請用 **設定 › AI 服務 › 儲存並測試連線**）
- 加入主畫面後的實際外觀與離線開啟（離線測試只在 Chromium 上跑）

## 開發

```
cd web
npm install
npm run dev          # 開發伺服器 http://localhost:5173
npx vitest run       # 單元與整合測試
npx playwright install chromium webkit
npx playwright test  # 端對端測試
npm run build        # 正式建置到 web/dist
```

程式結構：

```
web/src/
├── core/        純邏輯（從 KLinguaCore 移植）：韓文拆字、Drill 評分、SRS、分級、課表、週報、語音比對、AI、WAV
├── content/     直接匯入 iOS 版的教材 JSON（Packages/KLinguaCore/Sources/KLinguaCore/Content）
├── data/        本機資料庫（IndexedDB）、StudyStore、備份
└── app/         畫面（Preact）、路由、語音合成與辨識
```
